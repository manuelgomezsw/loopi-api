## Implementation Phases

### Phase 0: Verification & Preparation

- Confirm constitution compliance checks pass (table above)
- Search for existing code to reuse
- Confirm no naming conflicts with existing entities/services
- Confirm DB migration required or not

### Phase 1: Domain & Repository Layer

1. Add/update entity in `internal/domain/entity/` if needed
2. Add method to repository interface in `internal/domain/repository/`
3. Write pure domain logic in `internal/domain/<domain>/` if needed

### Phase 2: Infrastructure Layer

1. Implement repository method in `internal/infrastructure/repository/mysql_<domain>_repository.go`
2. Write or update DB migration in `migrations/` if schema changes

### Phase 3: Application (Service) Layer

1. Implement service method in `internal/application/service/<domain>_service.go`
2. Add structured logging with `logger.FromContext(ctx)` at INFO/WARN/ERROR as appropriate
3. Use `pkg/errors` for all domain errors

### Phase 4: Interface (Handler) Layer

1. Implement handler method in `internal/interface/handler/<domain>/`
2. Use `response.RespondJSON` / `response.RespondError` / `response.RespondSuccess`
3. Register new route in `internal/interface/router/router.go`

### Phase 5: Tests

1. 🔴 Write failing tests (fakes implementing repository interfaces)
2. 🟢 Run tests, confirm pass
3. 🔵 Refactor, confirm still passing
4. `make test-coverage` — confirm ≥ 80% coverage for new code
